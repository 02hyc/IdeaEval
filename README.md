# IdeaEval

**Impact-oriented evaluation of scientific hypothesis generation: benchmark, evaluator and ideation baselines.**

📝 Blog post: [English](https://02hyc.github.io/Blog/posts/ideaeval/) · [中文](https://02hyc.github.io/Blog/posts/ideaeval-zh/)
🤗 Data: [IdeaEval-Bench](https://huggingface.co/datasets/Yukino13/IdeaEval-Bench) · [IdeaEval-Calibration](https://huggingface.co/datasets/Yukino13/IdeaEval-Calibration) · [IdeaEval-Corpus](https://huggingface.co/datasets/Yukino13/IdeaEval-Corpus)

IdeaEval asks whether an AI-generated research proposal would have been worth more to the field than the work humans actually did on the same problem at the same time. It turns recent arXiv papers back into pre-experiment proposals, groups them into cohorts that share a research question and a time window, and asks an ideation system to write a proposal for the same question with only the literature available before the cohort's cutoff date. An evaluator then compares the AI proposal against each human proposal in the cohort.

**This project did not reach a positive result.** The evaluator agrees with citation-based labels on human-vs-human pairs, but it cannot reliably tell when an AI proposal is fundamentally flawed, so we could not produce trustworthy scores for ideation systems. The blog post explains what we tried and where it broke. We are releasing everything in case it is useful to whoever tries this next.

## What's in this repository

| Directory | What it does |
|---|---|
| [`benchmark/`](benchmark/) | Builds the benchmarks: arXiv corpus (Sep 2025 – Jan 2026) → research-question clustering (modified TaxoAdapt) → 31-day cohorts → date-leak checks → paper-to-proposal conversion. |
| [`evaluator/`](evaluator/) | The pairwise ranker: a literature-review agent, per-proposal analysis agents and a judge agent, plus the calibration runner. |
| [`baselines/`](baselines/) | Ideation baselines: Claude Code or Codex with cutoff-restricted literature tools writes a proposal for each cohort. |
| [`docs/`](docs/) | [`search_backend.md`](docs/search_backend.md): the cutoff-aware search interface the agents expect, and public components for building one. |

Each directory is a self-contained [uv](https://docs.astral.sh/uv/) project with its own README.

## Data

| Dataset | Contents |
|---|---|
| **IdeaEval-Corpus** | 35,505 arXiv papers (cs.LG, cs.AI, cs.CL, cs.CV, stat.ML; Sep 2025 – Jan 2026) with metadata, abstracts and Semantic Scholar citation counts. |
| **IdeaEval-Bench** | The ideation benchmark: 91 cohorts over 40 topics, 1,330 human proposals converted from papers, cutoff dates and research-direction prompts, plus the proposals generated by the ideation baselines. |
| **IdeaEval-Calibration** | 160 labeled proposal pairs for calibrating the evaluator (citation-based, synthetic-derivative and hand-labeled human-vs-AI), with pre-built literature-review workspaces. |

Proposals are LLM-generated rewrites of the source papers. The papers themselves are not redistributed; every record links to its arXiv id.

## Quick start

```bash
git clone https://github.com/02hyc/IdeaEval && cd IdeaEval

# Judge a calibration set (needs only model API keys)
cd evaluator && uv sync && cp example.env .env   # add keys
huggingface-cli download Yukino13/IdeaEval-Calibration --repo-type dataset --local-dir data/calibration
uv run python scripts/run_literature_archive_judge_manifest.py \
  --dataset data/calibration/setA/manifest.json --proposal-root data/calibration \
  --output-root experiments/setA --judge-model claude-opus-4.6 --random-order-seed 42
```

Running the baselines or the full three-stage ranker also requires a cutoff-aware search backend. The one we used was internal, so see [`docs/search_backend.md`](docs/search_backend.md) for how to stand one up.

## Results reported in the blog post

Ideation baselines on the 91 cohorts, judged by the Opus 4.6 judge (win rate against all human proposals in the same cohort). Treat these with caution: the judge itself is not reliable.

| Ideation system | Win rate |
|---|---|
| GLM-5.1 + Claude Code | 78.8% |
| Opus 4.6 + Claude Code | 75.5% |
| DeepSeek-V4-Pro + Claude Code | 69.4% |
| GPT-5.4 + Codex | 54.6% |
| Kimi-K2.6 + Claude Code | 50.7% |

Judge accuracy on 75 hand-labeled human-vs-AI pairs:

| Judge | Overall | AI better (18) | Human better (57) |
|---|---|---|---|
| GPT-5.4, original rubric | 49.3% | 83% | 39% |
| GPT-5.4, restructured rubric | 45% | 89% | 32% |
| Opus 4.6, forced verification | ~43% | 100% | 32% |
| GPT-5.5, forced verification | 45% | 67% | 39% |

The calibration data released here is a later, cleaned 160-pair set rather than the exact 260/250/75-pair sets in the blog. See the IdeaEval-Calibration dataset card for the mapping and for the current judge's results.

## Known limitations

- **No perfect proxy for an idea's value.** Citations also reflect topic popularity, author reputation, code release and much else. Human-vs-AI labels depend on the quality of our own annotation, which was not cross-checked.
- **Hindsight in paper-to-proposal conversion.** Results are removed, but the reconstructed proposals inherit the finished paper's structure and choices, which makes them more coherent and more conservative than real pre-experiment proposals.
- **Pairwise judging amplifies systematic bias.** When two proposals are close, the judge's preferences (polish, familiarity) decide.
- **Model knowledge cutoff.** The benchmark window was chosen to postdate the training cutoffs of GPT-5.4 and Opus 4.6. Newer models may have seen these papers.
